# Contributing to MAP Spec

Thank you for your interest in contributing to MAP Spec — the open standard for AI-ready software specifications.

## Ways to Contribute

### 1. Propose a Change to the Standard
Open a [GitHub Discussion](https://github.com/Izhar-3212/map-spec/discussions) with:
- The problem you've identified
- Your proposed change
- Why it makes MAP Spec better

### 2. Submit an Example Project
Add a real-world MAP Spec example to `/examples/` via Pull Request.

### 3. Report an Ambiguity
If any part of the standard is unclear or ambiguous, open an issue. Clarity is core to MAP Spec.

### 4. Build a Tool
Build a validator, generator, or IDE plugin that supports MAP Spec. List it in the ecosystem.

## Guiding Principles for Changes

Every proposed change must satisfy:

1. **Clarity** — does it make specs less ambiguous?
2. **AI-optimised** — does it help AI produce more accurate output?
3. **Human-readable** — can a developer read and write it without tooling?
4. **Stack-agnostic** — does it work for any technology stack?
5. **Backwards compatible** — does it break existing valid specs?

## Versioning

MAP Spec follows semantic versioning:
- **Patch** (1.0.x) — clarifications, typo fixes
- **Minor** (1.x.0) — new optional fields, new examples
- **Major** (x.0.0) — breaking changes to the schema

## Code of Conduct

Be respectful. Focus on the standard, not personalities. The goal is the best possible specification standard for the industry.
